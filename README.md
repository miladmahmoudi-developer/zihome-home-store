# فروشگاه زی‌هوم

یک فروشگاه محلی برای محصولات خانه که با React و Vite ساخته شده است. سرور Express
اطلاعات محصولات را در فایل JSON پروژه ذخیره می‌کند؛ برای استفاده از فروشگاه به
پایگاه دادهٔ آنلاین نیاز نیست.

## نقشه و توضیحات پروژه

- [نقشهٔ معماری ساده](docs/architecture.md): ارتباط صفحه‌ها، سرور، فایل محصولات،
  عکس‌ها و سبد خرید را با نمودار و مثال توضیح می‌دهد.
- توضیحات انگلیسی داخل فایل‌های `src/` و `server/` مسئولیت فایل‌ها و منطق بخش‌های
  مهم را شرح می‌دهند.

## اجرای پروژه روی کامپیوتر

قبل از شروع، Node.js نصب باشد. سپس در پوشهٔ پروژه ترمینال باز کن و یک بار
وابستگی‌ها را نصب کن:

```bash
npm install
```

این فرمان کتابخانه‌های لازم مثل React و Express را از روی `package.json` نصب
می‌کند. بعد دو ترمینال باز کن و هر دو را تا وقتی با سایت کار می‌کنی باز نگه دار.

در ترمینال اول سرور محصولات را اجرا کن:

```bash
npm run server
```

در ترمینال دوم برنامهٔ وب را اجرا کن:

```bash
npm run dev
```

Vite آدرس‌های `/api` را به سرور محلی روی پورت `3001` می‌فرستد. برای همین هر دو
ترمینال باید باز بمانند تا محصولات و صفحهٔ وب کار کنند.

آدرس سایت را Vite در ترمینال دوم چاپ می‌کند؛ معمولاً آدرسی شبیه
`http://localhost:5173` است. برای خاموش‌کردن هر برنامه، داخل ترمینال خودش
`Ctrl+C` را بزن.

## نقشهٔ راه در پوشه‌ها

```text
home-store/
├── index.html                  درِ ورودی‌ای که مرورگر باز می‌کند
├── package.json                نام برنامه و فرمان‌ها و کتابخانه‌های لازم
├── vite.config.js              تنظیم Vite و رساندن درخواست‌های /api به سرور
├── src/
│   ├── main.jsx                React را روشن می‌کند
│   ├── App.jsx                 ابزارهای مشترک برنامه را دور صفحه‌ها می‌گذارد
│   ├── index.css               ظاهر پایه و رنگ‌های مشترک سایت
│   ├── routes/AppRoutes.jsx    آدرس‌ها را به صفحه‌ها وصل می‌کند
│   ├── layouts/MainLayout.jsx  سربرگ، جای صفحه و پابرگ مشترک
│   ├── pages/                  خود صفحه‌های فروشگاه
│   ├── components/             تکه‌های قابل استفادهٔ دوباره
│   ├── services/                پل درخواست‌های مرورگر به API
│   ├── context/                 نگهداری وضعیت مشترک سبد
│   └── hooks/                   راه سادهٔ استفاده از منطق مشترک
├── server/
│   ├── index.js                 سرور محلی و مسیرهای API
│   └── data/products.json       دفتر اطلاعات محصولات
├── public/                      عکس‌ها و فایل‌هایی که صفحه نشان می‌دهد
└── docs/architecture.md         نقشهٔ کامل و توضیح سادهٔ ارتباط بخش‌ها
```

وقتی می‌خواهی چیزی را پیدا کنی، از این راهنما استفاده کن:

- متن یا چیدمان یک صفحه؟ اول فایل همان صفحه را در `src/pages/` ببین.
- ظاهر کارت محصولات؟ `src/components/ProductCard.jsx`.
- راه ارتباط با محصولات؟ `src/services/productService.js`.
- منطق سبد؟ `src/context/CartProvider.jsx` و `src/hooks/useCart.js`.
- رفتار سرور یا آدرس‌های API؟ `server/index.js`.
- محصول‌های ثبت‌شده؟ `server/data/products.json`.
- لوگو، بنر یا عکس ثابت؟ `public/`.

## بخش‌های مهم پروژه

| مسیر | کاربرد |
| --- | --- |
| `src/pages/` | صفحهٔ خانه، فروشگاه، جزئیات محصول، سبد و مدیریت |
| `src/components/` | اجزای قابل استفادهٔ دوباره، مثل کارت محصول |
| `src/services/productService.js` | فرستادن درخواست‌های محصول از React به API |
| `src/context/` و `src/hooks/` | نگهداری و دسترسی مشترک به سبد خرید |
| `src/index.css` | تنظیم ظاهر پایه، جهت راست‌به‌چپ و رنگ‌های مشترک |
| `vite.config.js` | تنظیم سرور توسعه و فرستادن `/api` به Express |
| `package.json` | فهرست کتابخانه‌ها و فرمان‌هایی مثل `dev` و `server` |
| `server/index.js` | API محلی برای خواندن، ساختن، ویرایش و حذف محصول و آپلود عکس |
| `server/data/products.json` | فهرست محلی محصولات |
| `public/` | بنرها، لوگو و عکس‌های نمایشی |
| `public/products/` | عکس‌هایی که از فرم مدیریت محصول آپلود می‌شوند |

## فرمان‌های آماده

```bash
npm run lint
npm run build
```

`lint` خطاهای رایج کدنویسی را پیدا می‌کند. `build` نسخهٔ قابل انتشار برنامه را
در پوشهٔ `dist/` می‌سازد.

## صفحه‌ها و نشانی‌هایشان

| نشانی سایت | کاری که می‌کند |
| --- | --- |
| `/` | صفحهٔ اصلی؛ بنرها، دسته‌بندی‌ها و محصولات ویژه |
| `/shop` | همهٔ محصولات با جست‌وجو، فیلتر دسته و مرتب‌سازی |
| `/products/شناسه` | جزئیات یک محصول؛ شناسه از اطلاعات محصول می‌آید |
| `/cart` | دیدن و تغییر تعداد کالاهای سبد |
| `/admin/products` | دیدن، ویرایش یا حذف محصول‌های ثبت‌شده |
| `/admin/products/new` | بازکردن فرم ثبت محصول تازه |
| `/admin/products/شناسه/edit` | ویرایش محصولی که شناسه‌اش در آدرس است |

صفحهٔ مدیریت فعلاً برای پروژهٔ محلی آموزشی است و ورود با نام کاربری و رمز ندارد.

## از کجا می‌آیند و کجا می‌روند؟

وقتی صفحه فهرست محصول‌ها را می‌خواهد، مسیر ساده‌اش این است:

```text
صفحهٔ React
  → productService
  → درخواست /api
  → Vite آن را به سرور Express می‌رساند
  → server/index.js فایل products.json را می‌خواند
  → جواب به صفحه برمی‌گردد
```

وقتی محصول تازه می‌سازی، اول عکس به سرور می‌رود. سرور عکس را در
`public/products/` می‌گذارد و نشانی آن را برمی‌گرداند. فرم آن نشانی را همراه
نام، قیمت و بقیهٔ اطلاعات به API می‌فرستد. سرور اطلاعات محصول را در
`server/data/products.json` ذخیره می‌کند.

## آدرس‌های API

این آدرس‌ها برای ارتباط برنامهٔ React با سرور محلی هستند. وقتی در نوار مرورگر
`/api` می‌بینی، این مسیر مخصوص گفت‌وگوی برنامه با سرور است.

| روش و آدرس | کار |
| --- | --- |
| `GET /api/products` | فرستادن فهرست همهٔ محصولات |
| `GET /api/products/:id` | پیدا کردن یک محصول با شناسه |
| `POST /api/products` | ذخیرهٔ محصول تازه |
| `PATCH /api/products/:id` | ذخیرهٔ تغییرات یک محصول |
| `DELETE /api/products/:id` | حذف یک محصول |
| `POST /api/uploads` | ذخیرهٔ عکس انتخاب‌شده و برگرداندن نشانی آن |

`GET` یعنی «بخوان»، `POST` یعنی «بساز یا بفرست»، `PATCH` یعنی «ویرایش کن» و
`DELETE` یعنی «پاک کن». فهرست دسته‌ها API جداگانه ندارد؛ برنامه آن را از روی
محصول‌ها می‌سازد.

## سه جای متفاوت برای ذخیره‌کردن

| داده | محل ذخیره | یعنی چه؟ |
| --- | --- | --- |
| اطلاعات محصول | `server/data/products.json` | با خاموش‌کردن برنامه پاک نمی‌شود؛ فایل را سرور دوباره می‌خواند. |
| عکس آپلودشدهٔ محصول | `public/products/` | یک فایل عکس واقعی در پوشهٔ پروژه است. |
| سبد خرید | `localStorage` مرورگر | در همین مرورگر و همین دستگاه می‌ماند؛ هنوز روی سرور ذخیره نمی‌شود. |

## اگر چیزی کار نکرد

- **صفحه باز نمی‌شود:** مطمئن شو `npm run dev` در یک ترمینال هنوز در حال اجراست.
- **محصول‌ها بارگذاری نمی‌شوند:** ترمینال سرور را ببین؛ `npm run server` هم باید
  در ترمینال دیگری فعال باشد.
- **افزودن محصول یا عکس خطا می‌دهد:** هر دو برنامه را روشن نگه دار و پیام خطای
  صفحه و ترمینال سرور را بخوان. مسیر `/api` در `vite.config.js` به پورت `3001`
  وصل شده است.
- **عکس در صفحه دیده نمی‌شود:** مسیر عکس در محصول و نام فایل در `public/` یا
  `public/products/` باید با هم جور باشند.
- **فایل JSON را دستی عوض کردی ولی صفحه هنوز قدیمی است:** صفحه را تازه کن؛
  اطلاعات گرفته‌شده ممکن است موقتاً در cache مرورگر مانده باشد. اگر از فرم
  مدیریت ویرایش کنی، خود برنامه فهرست cache را تازه می‌کند.

## چند واژهٔ ساده

- **صفحه یا Page:** یک آدرس و یک بخش از سایت، مثل خانه یا سبد خرید.
- **کامپوننت یا Component:** تکه‌ای از صفحه که می‌توان در چند جا استفاده کرد.
- **سرور یا Server:** برنامه‌ای که داده را می‌خواند، بررسی می‌کند و ذخیره می‌کند.
- **API:** راهی که صفحه و سرور با هم پیام ردوبدل می‌کنند.
- **Cache:** یادداشت موقت برای اینکه دادهٔ تازه‌گرفته‌شده فوراً فراموش نشود.
- **State:** اطلاعاتی که هنگام کار با صفحه عوض می‌شوند؛ مثلاً متن جست‌وجو یا سبد.
